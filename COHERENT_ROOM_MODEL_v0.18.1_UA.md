# ELEKTORYK Smart Scan v0.18.1 — Coherent Room Model

Цей прохід виправляє проблеми, які були видимі на реальному тесті v0.18.0: 20–22 live-стіни в одній кімнаті, 7 випадкових ліній у 2D, зникнення вже просканованої сітки та повторення одного фото по всій 3D-стіні.

## Що змінилось

- Одна фізична площина дедуплікується перед live-відображенням і метрикою готовності.
- Маленькі вертикальні площини (одвірок, край шафи, меблі) не вважаються стабільною архітектурною стіною.
- Уже проскановані tiles зберігаються постійно в scan-local координатах і не зникають через 1.1 с.
- “Новий Smart Scan з нуля” тепер справді не підмішує стару point cloud; окрема дія “Досканувати” лишається для multi-pass fusion.
- Фінальна реконструкція має topology guard: якщо детектор видає неможливу кількість стін, користувачу не показується ліс ліній.
- Виправлено баг OpeningDetector: support має діапазон 0..1, але код порівнював його з 2.
- Додано пошук дверних/віконних прорізів усередині однієї безперервної стіни.
- RAW texture тепер мозаїка по фізичних координатах стіни з кількох RGB keyframes, без TileMode.REPEAT.
- Слабко підтверджений fallback-периметр лишається low-confidence і не видається за готовий скан.

## Перевірки

Synthetic: 4 справжні стіни + великий меблевий об'єм + дверний проріз -> 4 стіни, 1 кімната, 1 двері.
Synthetic window profile -> WINDOW 1.2 м.
Pure-Java compile-check для зміненого reconstruction core, DepthSurfaceTracker та ArSurfaceGridRenderer проходить.
WallTextureBaker окремо проходить Java compile-check зі stub Android/ARCore API.

## Чесне обмеження

Depth сам по собі не може надійно назвати дзеркало/шафу/диван. У цій версії невідомий внутрішній об'єм лишається об'єктом, а не перетворюється на стіну. Повний semantic label потребує реально вбудованої indoor RGB segmentation-моделі; її тут не симулюють евристикою.
