# ElektorykScan v0.20.5 — Opening / room topology pass

Цей прохід сфокусований на помилках, через які двері/вікна могли псувати multi-room модель навіть при нормальній геометрії.

## Реально виправлено

- `OpeningDetector.pathCrosses()` більше не вважає просте проходження **паралельно біля стіни** доказом дверей. Тепер траєкторія повинна реально перетнути лінію стіни в межах фізичного пройому (з малим допуском).
- `MultiRoomSegmenter.assignOpenings()` переписано на нормаль стіни: для горизонтальної стіни кімнати шукаються по ±Z, для вертикальної — по ±X. Старий код міг шукати вздовж стіни і прив'язувати не ту кімнату.
- Додано захист від ситуації, коли обидві сторони пройому через шум потрапляють у ту саму кімнату.
- `external` для пройомів тепер перераховується з фактичної топології кімнат; вікно примусово не створює room-to-room зв'язок.
- Семантичні RGB door/window, додані після Depth-реконструкції, тепер отримують правильну orientation, roomA/roomB та external замість дефолтної `HORIZONTAL_X` і порожньої топології.
- Після ручного редагування типу/розміру пройому редактор повторно прив'язує його до кімнат і оновлює exterior-стан.

## Чому це важливо

Ці помилки напряму впливали на multi-room: двері могли з'єднувати неправильні зони, вікно могло виглядати як зв'язок між кімнатами, а рух уздовж стіни міг дати хибний door evidence.
